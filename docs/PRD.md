# PRD: 메시지 작성 웹사이트 (가칭)

## 1. 개요
- 한 줄 요약: 보내는 **상황·대상·플랫폼**에 맞는 '적절한' 메시지를 추천. 검토·수정 후 사용자가 직접 전송
- 핵심 가치: 대상/상황/플랫폼 등에 따라 사회적으로 **무슨 말을 어떻게 해야 적절한지** 고민을 대신 풀어줌
  - ① 맥락 맞춤 멘트 추천: 상황에 맞는 인사·감사·마무리 등 적절한 말 제안
    - 하고 싶은 말 없이도 가능 (대상·상황만으로 보낼 말 추천)
  - ② 하고 싶은 말 다듬기: 내가 적은 말을 정중·자연스러운 문장으로
  - 자유도 조절바(F3)가 두 축의 비율을 조절: 왼쪽 끝 = 다듬기만, 오른쪽 끝 = 추천 적극 반영
- 맥락 3요소: 상황(F2) · 대상(F1 받는 사람) · 플랫폼(F1 채널)
  - 같은 말도 3요소에 따라 다른 메시지가 나옴 (예: 처음 보내는 대표님께 카톡 vs 친한 선배에게 인스타 DM)
- 해결할 문제
  - 이 상황·상대·채널에서 어떤 말이 적절한지 몰라 고민됨
  - 하고 싶은 말은 있는데 정중·자연스럽게 쓰기 어려움
  - AI 앱 ↔ 메신저 오가며 복붙하는 번거로움
- 말투 변환·문법 교정 중심 도구와의 차이: 맥락을 보고 **적절한 말 자체를 제안**
- 대상: 선생님·대표님·담당자 등에게 카톡/SNS/이메일로 연락하는 사람 (1차: 본인)
- 형태: 모바일 우선 웹사이트 

## 2. 핵심 흐름
1. 입력: 받는 사람 · 상황(필수), 채널 · 하고 싶은 말(선택)
2. AI 자유도 조절바 설정
3. [만들기] → 완성본 1개 생성
4. 필요 시 버전 버튼(격식 / 캐주얼 / 영어 / 간결)·자유도 변경 → 새 완성본이 기존 완성본 아래에 추가 (스크롤로 여러 버전 비교)
5. 마음에 드는 완성본 선택 → 검토·직접 수정
6. [복사] 또는 [공유] → 메신저에서 사용자가 직접 전송
7. 받는 사람·상황을 바꿔 만들면 새 세션 시작. 이전 세션은 기록에 저장되어 나중에 다시 열 수 있음 (F6)

## 3. 기능 요구사항

### F1. 입력
- 받는 사람: 자유 입력 (예: 선생님, 처음 만난 대표님) — 필수, 최대 100자
- 존댓말 / 반말 토글로 사용자 지정(지정하지 않으면, 받는 사람에 따라 AI가 존댓말 사용 여부 판단)
- 하고 싶은 말: 자유 입력 (메모·반말·키워드 가능) — 선택 (비어 있으면 대상·상황에 맞는 말을 추천), 최대 2000자
- 채널: 선택 (카카오톡 / 인스타 DM / LinkedIn / 이메일)
  - 카톡·DM: 짧은 대화체
  - 이메일: 제목·인사·본문·맺음 구조
  - LinkedIn: 간결·전문적
  - 미선택 시: 채널 중립 문체

### F2. 상황 정보
- 필수 (칩 선택 또는 직접 입력 중 하나 이상), 최대 500자
- 자유 입력 + 추천 키워드 칩 (칩 선택·직접 입력 둘 다 가능)
- 칩 선택 시 입력창에 텍스트로 들어가 수정 가능
- 칩 초안 : 처음 인사 / 처음 네트워킹 / 부탁 / 질문 / 감사 / 사과 / 거절 / 일정 조율 / 후속 연락
- 다중 선택 가능


### F3. AI 자유도 조절바
- 왼쪽 끝: 내가 준 내용만 다듬기 ↔ 오른쪽 끝: AI가 적절한 말·표현 추가
- 3단계 (기본값: 2단계)

| 단계 | 허용 범위 |
|---|---|
| 1. 다듬기 | 맞춤법·말투·문장 정리만. 새 문장 추가 없음 |
| 2. 말투 보강 | 1단계 + 호칭, 인사, 완충 표현("혹시"), 감사, 마무리 인사 |
| 3. 멘트 추가 | 2단계 + 안부·공감, 관계 이어가기, 다음 행동 제안을 적극 포함 (구체 내용은 `[빈칸]`, 일반 칭찬·감상은 assumptions 기록) |

- 단계별 길이 기준: 1단계 입력과 거의 같게(±20%) / 2단계 약 1.5~2배 / 3단계 약 2.5~3배 (2단계보다 확실히 길고 풍부하게)
- 하고 싶은 말이 비어 있을 때: 1단계는 대상·상황에 맞는 아주 일반적인 말만 보수적으로 추천(1~2문장), 2단계 3~5문장, 3단계 6~9문장
- 모든 단계에 4번 생성 규칙 적용

### F4. 결과
- 최초 생성 시 완성본 **1개**만 표시
- 이후 버전 버튼(격식 / 캐주얼 / 영어 / 간결) 또는 자유도 변경 후 생성하면 **새 완성본이 기존 완성본 아래에 추가**
  - 스크롤로 여러 버전을 동시에 나열·비교 (교체·되돌리기 없음)
  - 격식·캐주얼·간결 버튼: 같은 입력·같은 자유도로 해당 버전 생성
  - 영어 버튼: 입력에서 새로 만들지 않고 **직전 완성본(직접 수정한 내용 포함)과 제목을 영어로 번역**해 새 완성본으로 추가 (자유도·입력 변경과 무관, 번역 원문 최대 4000자)
  - 자유도 변경: 바 조정 후 [다시 만들기]로 생성 
  - 각 완성본에 생성 조건(버전·자유도 단계) 라벨 표시 
- AI가 가정한 부분이 있으면 해당 완성본 아래 한 줄로 표시 

### F5. 검토·내보내기 (승인 단계)
- 각 완성본마다 직접 수정 / [복사] / [공유](OS 공유 시트) 가능
  - [공유]는 Web Share API를 지원하는 브라우저에서만 표시 (미지원 시 [복사]만)
  - 이메일 완성본: 제목과 본문을 따로 수정·복사. [공유] 시에는 제목을 본문 앞에 붙여 전달
- 최종 전송은 사용자가 메신저에서 직접. **자동 전송 없음**

### F6. 세션·기록
- 세션: 받는 사람·상황이 같은 완성본 묶음
- 받는 사람 또는 상황(앞뒤 공백 무시)을 바꾼 뒤 [만들기]·버전 버튼으로 생성하면 새 세션 시작 (입력 중에는 전환 안 함)
  - 채널·존댓말·하고 싶은 말·자유도만 바꾸면 같은 세션에 추가 ('입력 수정됨' 라벨)
  - 영어 번역은 항상 현재 세션에 추가
- 완성본이 1개 이상 생긴 세션만 기록에 저장. 직접 수정한 내용도 저장
- [기록]: 최근 수정 순 목록, 받는 사람·상황·완성본 내용으로 검색, 항목별 삭제
- 기록에서 열면 입력·자유도·완성본을 복원하고, 이어서 생성한 완성본은 그 세션에 추가
- [새로 쓰기]: 입력을 비우고 새 세션 시작
- 저장 위치: 현재는 브라우저(localStorage). 이후 Supabase로 이전 (저장소 계층만 교체)
- 저장에 실패하면 "기록을 저장하지 못했어요" 알림 표시

### F7. 사용 한도·접근 정책
- 로그인·접속 코드 없이 누구나 사용
- **서비스 전체가 함께 쓰는 하루 공용 한도**: 한국 시간 자정에 초기화 (값은 서버 DB에서 조정, Gemini 한도 확인 후 정함)
- 차감 단위: AI 호출 요청 1건 = 1회 (만들기·다시 만들기·버전 버튼·영어·재시도 모두 포함). 입력 검증에서 걸린 요청은 차감하지 않음
- 한도 소진 시: "오늘 사용 가능한 횟수가 모두 소진됐어요. 한국 시간 자정 이후에 다시 이용해 주세요." 안내
- 한도 확인 자체가 실패하면(DB·키 오류 등) 통과시키지 않고 "서비스를 준비 중이에요" 안내 (fail closed)
- 단시간 몰림 방지: IP당 분당 10회 제한 (배포 환경 적용, 로컬 개발 서버 미적용). 초과 시 "1분 뒤 다시 시도" 안내
- Gemini 무료 한도 초과(429) 시 "AI 사용량이 많아요" 안내
- 개인정보 안내: 화면 상단에 상시 표시. 입력이 Google AI(Gemini)로 전송되며, 무료 단계에서는 Google이 서비스 개선에 사용하거나 사람이 검토할 수 있으므로 실명·연락처·주소 등 민감한 개인정보를 넣지 않도록 안내
- 서버(Supabase)에는 **사용 횟수만 저장**. 입력·완성본은 서버에 저장하지 않음

## 4. 생성 규칙 (모든 자유도 공통)
- 사용자 의도 유지 (질문→질문, 부탁→부탁, 거절→거절)
- 사용자에 대한 **구체 사실**(이름·소속·직함·날짜·시간·장소·수치·참석 여부·과거 사건)은 지어내지 않음
  - 필요하면 `[이름]` 같은 빈칸으로 남김
  - 이유: 메시지가 사용자 이름으로 나가기 때문
  - 구체 사실 없이 쓰는 **일반적인 칭찬·감상 표현**(예: "좋은 말씀 감사했습니다")과 관계·존댓말 추정은 허용하되, 어떤 가정을 했는지 assumptions에 기록 (3단계에서 특히 적극 사용)
- 길이는 자유도 단계의 길이 기준을 따름 (F3 참고. 1단계는 입력 분량 유지, 높은 단계일수록 풍부하게)
- 받는 사람 관계에 맞는 존댓말 수위
- 딱딱한 문어체보다 자연스러운 한국어 우선

## 5. MVP 범위
- 포함: F1~F7 (기록은 브라우저 저장, Supabase는 하루 사용 한도 관리에만 사용)
- 제외(후속)
  - 직접 전송 (Gmail 등 공식 연동 가능한 채널부터)
  - 로그인·입력/완성본·기록의 서버 저장(Supabase)·기기 간 동기화
  - 받은 메시지 읽고 답장 만들기
  - 멘트 후보 칸별 교체
- 직접 전송 제외 근거
  - 카톡 친구에게 직접 전송: 공식 경로상 상대도 앱 로그인·동의 필요 → 사실상 불가
  - 인스타·LinkedIn·스냅챗 DM: 개인용 공식 연동 미확인

## 6. 구현 시 주의
- AI 호출은 서버를 거침 (API 키를 화면 코드에 넣지 않음)
  - 서버 전용 환경변수: `GEMINI_API_KEY`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY` (`VITE_` 접두사 금지, 깃·채팅에 노출 금지). 배포 시 Netlify 환경변수에도 설정
  - AI 호출은 서버 함수 한 곳(`netlify/functions/generate.ts`)에 모아 두어 AI 공급자 교체가 쉽게 유지
  - Supabase 표는 RLS를 켜고 브라우저용 접근 정책은 두지 않음 (서버 함수만 비밀 키로 접근)
- 공유 기능(Web Share API)은 사용자가 버튼을 누른 직후에만 호출 가능 → [공유]는 생성과 분리된 별도 버튼
- 아이폰 사파리에서 먼저 테스트
- 카톡·인스타·스냅챗에서 공유 시 글이 실제로 넘어오는지 **직접 확인 필요 (미검증)**
- 입력·완성본은 브라우저(localStorage)에만 저장. 서버(Supabase)에는 사용 횟수만 저장 (입력·완성본 서버 저장은 후속)

## 7. 성공 기준 **(제안)**
- 자연스러움: 본인 평가 5점 만점에 4점 이상
- 새로 들어간 **구체 사실**(이름·날짜·수치·소속·과거 사건 등): 0개 (모든 자유도 단계). 일반 표현·추정은 assumptions에 기록되면 허용
- 기존 방식(AI 앱 → 복붙) 대비 걸린 시간·터치 수 감소

## 8. 미결정
1. 직접 전송 도입 시점과 첫 채널
2. 자유도 연속 조절 도입 여부 (현재 3단계로 구현)
3. 입력·완성본·기록의 서버 저장 도입 시 사용자 식별 방식 (익명 인증 / 로그인)과 기존 브라우저 기록 이전 방법 (Supabase는 현재 하루 한도 관리에만 사용)
4. 하루 공용 한도 값: Gemini 무료 한도(AI Studio에서 확인) 기준으로 정하고, 실제 사용 패턴을 보며 조정
5. Gemini 무료 단계의 분당 한도(429): 연속 요청 시 실패 원인 확인 및 대응 (우리 쪽 분당 제한, 버튼 연타 방지 등)
6. Gemini 호출이 실패했을 때 이미 차감된 횟수를 돌려줄지 (현재는 돌려주지 않음)
7. 무료 단계 유지 vs 유료 전환: 무료 단계는 입력이 Google 개선·검토에 쓰일 수 있음 (F7 안내 문구로 대응 중)

### 결정됨 (참고)
- 칭찬·감상 멘트: 일반 표현은 허용하고 assumptions에 기록, 구체 사실은 빈칸 (§4)
- 영어 버전: 직전 완성본 번역 방식 (F4)
- 접근 정책: 코드·로그인 없이 공용 하루 한도 (F7)
